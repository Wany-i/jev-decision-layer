## 结论摘要

1. **中文图文圈覆盖充足，视频圈几乎空白。** 36氪/极客公园/机器之心/腾讯新闻/网易/搜狐/新浪财经/53AI/DataLearner/雪球/微博均已有介绍文；但 **B站、抖音、小红书、知乎四个平台的 Jev 专属内容经定向检索均为零命中**（对照词验证通道有效，见下）。
2. **中文圈已明确讨论"怎么用上它"**：网易号《2条路抢先跑Jev：候补排队，Vercel已能调用》；微博有账号指出"目前在一些三方聚合 maas 平台 openrouter 上已经开放 API"。
3. **YouTube 侧至少 3 个第三方讲解视频存在**（Sam Witteveen、TheAIGRID、Patrick Desjardins），但**我只拿到 1 个确切视频 ID（`goVDTUd7-J0`）**，其余仅有二手摘要描述，未取得直链与标题原文——按纪律如实标注。
4. **中文输入/输出的表现，中文圈没有人给出实测。** 唯一相关是 DataLearner 条目转述"英文是主要训练语言且效果最好，其他语种（包括 CJK 文字）支持不均衡"；53AI 文章建议"先准备一批人工标注过的中文稿"再自测——**说明中文效果当时无人验证**。
5. **门槛问题被反复提及**：官方 waitlist 排队 + 需要海外通道（Vercel AI Gateway / OpenRouter / 官方 API）+ 外币支付。中文圈普遍把它当"看得到、够不着"。
6. **三个中文说法的核查结论：三个都找到了原始出处**，但**都有口径缩水或夸大**——马里奥=独立 GitHub 实验仓库；航班 7 秒=开源浏览器 agent 的"搜出结果页"用时（非订票）；交易机器人=默认 mock/dry-run 的开源实验（无盈亏验证）。
7. **中文圈最热的一篇是数字生命卡兹克的文章**（微信/网易号，2026-09-18），"马里奥/航班7秒/交易机器人"三个说法**正是从这篇文章的转述进入中文圈的**，而该文本身是二手转述。

1. **访问资格**：官方 early access + 候补名单，多篇文章写"提交申请后等待放量"。有英文侧说法称"waitlist clears in about a day"（https://agihunt.info/en/p/1a0b2f347fc502b04cf8dcdc3a4），但**中文圈多为转述，未有人给出国内申请通过的时间记录**。
2. **网络**：Vercel/OpenRouter 均需海外通道；国内直连海外 API 的延迟问题被通用讨论（"国内直连 TTFB 往往超过 3000 毫秒"，https://www.toutiao.com/article/7670827877633507867/ ），但**该文并非针对 Jev**。
3. **支付**：OpenRouter 不支持人民币/支付宝/微信，"需要 Visa/Mastercard 外币信用卡或加密货币充值"（https://blog.csdn.net/weixin_29483277/article/details/163600165 、https://aiproducthub.cn/?p=6229/ ）。**这些是 OpenRouter 通用门槛，不是 Jev 专属的抱怨；我没有找到任何中文用户专门抱怨"Jev 支付/额度"问题。**
4. **额度/计费误解**：53AI 明确纠正过一次误读：`它是收费服务，"输出免费"也不代表整个请求免费。`

### 四、有无人实测
- **中文圈：无。** 没有检索到任何中文开发者给出 Jev 的自建评测、延迟曲线或误判率。
- **非中文圈倒是有多家第三方实测**（供对照，非本路重点）：
  - Michael Lee：约 5,000 次请求约 $2，p50 ~150ms / p95 ~350ms（https://aisocratic.org/news/chatgpt-co-inventor-diogo-almeida-launches-jev-a-decision-model-he-says-is-20200x-faster-than-frontier-llms）
  - Every / Dan Shipper：777 次判断 <0.7 秒，12 段文本埋 7 个缺陷抓到 6 个（中文圈多篇转述，如新浪财经 https://finance.sina.cn/tech/2026-09-17/detail-inisatui4277738.d.html ）

  - **注意**：@jiayuan_jy 的结论是 "Jev 本质上是更快的通用分类器/决策器，**LLM 可以做同样的事，它的优势只是速度**"，且怀疑其参数规模不大、可能缺乏世界知识。

## 「马里奥 · 航班 7 秒 · 交易机器人」三说的出处核查

> 背景：主 agent 提示这三个说法来自"来源不明"的中文转述。核查结果：**三个都找到了原始出处**，且都指向具体 GitHub 仓库/项目文档。同时确认它们进入中文圈的路径。

### 核查 0：三个说法进入中文圈的路径（先说清楚）
三个说法在中文圈口径下**同时出现在同一篇文章里**——数字生命卡兹克《这个只会做选择题的Jev，却是今年我看到的最特别的大模型。》，2026-09-18（微信公众号首发，网易号转载 https://www.163.com/dy/article/L73I8B8T055627NS_pdya11y.html ）。
原文摘录（三个说法在同一段）：
> `网上的大佬们已经玩疯了。比如,有人会用它,玩马里奥,因为马里奥本质上也就是按键判断。。。效果出奇的好。有人用它操控浏览器查询航班,一共就花了7秒,全部点完,毕竟,浏览器操控,本质上也是判断决策。还有大佬用它搭了一个交易机器人,因为做交易,本质上也是决策,就是买或者卖而已。`

**该文是第一手实测（它自己测了 X 过滤插件）+ 二手转述（这三个海外案例）的混合体。** 三个案例本身在该文中**没有给出任何链接**，属于转述。所以"来源不明"的观感是对的——**不是说法假，而是转述者没给出处**。

### 核查 1：马里奥（Mario）用例 —— **找到原始出处**
- **原始出处**：GitHub 仓库 **`fhshaik/typesafe-mario`**
  - URL：https://github.com/fhshaik/typesafe-mario
  - 原文摘录：`TypeSafe Mario — An experimental controller that lets TypeSafe's Jev model directly choose NES controller inputs for the original Super Mario Bros. The model does not receive screenshots.`
  - 架构：`NES emulator -> telemetry/RAM parser -> structured JSON -> Jev Choice -> controller input`；每次请求同时评估三个判断（Choice 选动作宏、Noul 估计前跳是否有用、Score 评当前危险度）；动作集很小：`noop / right / right_jump / right_run / right_run_jump / jump / left`。
  - 属性：**实验性控制器**，非成品；需自备合法 ROM；`--display none` 可跑 headless benchmark。
- **旁证（第三方整理）**：AGI Hunt 的六仓库盘点明确列出该仓库（https://agihunt.info/en/p/1a0b2f347fc502b04cf8dcdc3a4）；另一份中文/日文混合的"30 个活用案例"清单第 19 条同样描述该仓库，并提醒"能跑起来和每次都能稳定通关是两回事"。
- **中文圈转述链**：微博用户"蚁工厂"2026-09-17 发过一条（含视频）介绍该仓库，给出地址 `github.com/fhshaik/typesafe-mario`（https://m.weibo.cn/status/5344218513936902 ）；数字生命卡兹克文章的一行"玩马里奥"是对同一批素材的极简转述，**已丢失仓库链接与"实验性"限定**。
- **核查结论**：**找到原始出处（GitHub 仓库）**。中文转述把"实验性控制器"压缩成"效果出奇的好"，属**夸大**。

### 核查 2：航班 7 秒 —— **找到原始出处**
- **原始出处**：GitHub 仓库 **`browser-use/jev-ultrafast`** 及其官方性能文档
  - 仓库：https://github.com/browser-use/jev-ultrafast
  - 性能文档：https://github.com/browser-use/jev-ultrafast/blob/main/docs/performance.md
  - 原文摘录：`The current video completes the Google Flights task in 7.073 seconds at 1×.` / 中位优化组 7.092 s、原始组 9.450 s / `Median task time was 25.0% lower` / `Median Jev latency was 178 ms` / **`Three pairs are too few for a strong statistical claim (two-sided sign-test p = 0.25)`**
- **旁证**：英文报道 https://news.lavx.hu/article/jev-ultrafast-cuts-browser-agent-time-by-25-with-typesafe-action-space （写明 Zürich→London 单程、原 9.45s→7.1s、CDP 调用 1,092→101、91% 降幅）。
- **口径校正（重要）**：
  1. 数字是 **7.07–7.1 秒**，不是"7 秒整"；
  2. 任务是"**搜出符合条件的航班结果页**"，**不包含选票、付款、完成预订**——网易号标题《7.1秒**订完**机票》是标题夸张（正文其实写清了"没有选票、付款或完成预订"）；
  3. 该 7.1 秒**包含工程优化贡献**（批量读页面、并行选动作、减少浏览器通信），**不能全算在模型头上**；
  4. 作者自陈样本量小、统计力不足。
- **核查结论**：**找到原始出处**。中文转述在"订完机票"这一点上**失真**。

### 核查 3：交易机器人 —— **找到原始出处**
- **原始出处**：GitHub 仓库 **`jarrodwatts/jev-trader`**（作者 Jarrod Watts）
  - 第三方深度分析（含 README 逐条引用）：https://hysenlabs.com/en/projects/jarrodwatts-jev-trader
  - 原文摘录：`once every Monad block, roughly every 300 milliseconds, a TypeSafe Jev model looks at the Kuru MON-USDC order book and answers buy or sell` / `Dry run by default; live trading is one private key away.` / **`The default MODEL is mock, a momentum heuristic stand-in; setting MODEL=jev with a TYPESAFE_AI_API_KEY points the loop at the actual Jev model.`** / `Skip it if you need a proven strategy... or anything resembling investment advice`
  - 另有一条更早的第三方记录（含社区质疑）：https://agihunt.info/en/p/1a0ad20e8a8ee51277c23d48b93 —— `Commenters questioned the strategy (buy/sell flip-flopping on static prices, no P&L tracking); the author admitted it was rough but real, and subsequently open-sourced the code.`
- **口径校正（重要）**：
  1. **默认是 mock 模型 + dry-run（模拟成交）**，不开 Jev、不下真单；"用 Jev 跑实盘"是另一个配置；
  2. **没有盈亏验证**，README 明确不给投资建议、不保证盈利；
  3. 约 300 ms 是 Monad 出块节拍（设计约束），不是 Jev 的实测延迟；
  4. 代码需要处理"判断迟到就跳过本轮"的分支——说明它**不保证每次都赶得上**。
- **核查结论**：**找到原始出处**。中文转述"大佬用它搭了一个交易机器人"省略了 mock/dry-run/无盈亏这三个关键限定，属**严重省略**。
- **附带说明**：雪球那篇《Jev与大模型的高频交易时刻》是**中文圈自己的金融推演**（且自陈由 Gemini 执笔），与这个 GitHub 仓库**不是同一件事**，不要混为一谈。
