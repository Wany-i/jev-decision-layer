# 06 生态集成与框架支持

> 本文档由 **AI 进行调研、整理与提交**（2026-09-19）。证据分级与出处见文内标注；非官方材料，与模型厂商无隶属关系。

调研对象：`typesafe/jev-1.13`（别名 `jev-latest`），TypeSafe AI 2026-09-15 发布的 System One 决策模型
调研日期：2026-09-19
调研范围：谁已经接好了 Jev、谁还需要自己包、谁完全没有

---

## 结论摘要（≤10 行）

1. **官方接入路径是"Agent Skill"，不是 MCP，也不是框架 SDK**。`typesafe-ai/skills` 是官方 Claude Code 插件市场包（MIT，Release v0.5.7，Sep 12 2026），一条命令装进 Claude Code / Codex / 任意 skills.sh 兼容 agent。官方文档专页标题就叫 "Agent skill"，定位是"教 agent 怎么写 TypeSafe 代码"，**不是**让 Jev 变成 agent 的 tool。
2. **唯一有一等公民框架集成的两家是 LangChain 和 Vercel**：LangChain 出了 `langchain-typesafe`（`TypeSafeClassifier` Runnable + 2 个 experimental middleware）；Vercel 出了 AI SDK 7 的 `experimental_evaluate()` + `@ai-sdk/typesafe-ai` provider + Gateway 模型 ID `typesafe-ai/jev`。
3. **可观测层只有 Braintrust 做了专门适配**：`wrapTypeSafe()`、`braintrust/hook.mjs` 自动插桩，外加把 Jev 当 judge scorer。Langfuse / Arize Phoenix / W&B Weave 全部**无**专用适配（零命中），只能自己包一层 OTel span。
4. **执行层（浏览器/桌面）反而社区跑得最快**：`browser-use/jev-ultrafast`（用 Jev 选 operation + element，Google Flights 7.1s）和 `awlevin/typesafe-computer-use`（macOS OCR + Jev，单步 $0.0002）都是**真用了 Jev 做判断**，不是蹭名字。
5. **Python 侧"还能自己包"的大头**：LlamaIndex / Pydantic-AI / CrewAI / AutoGen / LangGraph / Composio / elizaOS 全部**零命中**，无官方也无社区集成。
6. **Rust（Rig）、TS 函数式（Effect）零命中**。Rig 的 provider 列表里没有 TypeSafe；Effect 只有 `@effect/ai-openrouter`，没有 typesafe。
7. **MCP 官方没有**。"MCP" 是社区自己包出来的（`jkudish/jev-mcp`、`blakestone-x/jev-mcp`、`decide-mcp`、`Jevbridge`），全部是 PoC 级别。
8. **guardrail / router 层（NeMo Guardrails / RouteLLM / semantic-router）零官方适配**，但社区造了一整族 `jev-router`（Claude Code 选模型、LiteLLM 路由、per-message reasoning effort），说明"决策模型当路由层"确实有人在做，只是没走上述三个框架。
9. **官方还埋了一个反向适配器**：`typesafe-ai/system-one-adapter-python`（v0.2.0, Sep 18 2026）把 `system_one` 接口换成 OpenAI/Anthropic 后端，让你在没排到队 / 想对比成本时也能先跑通代码。
10. **纠偏**：llms.txt 只列出 **18 个 cookbook**（背景里写 21）；`typesafe-ai` 组织 10 个仓库里有 2 个（`LLaDA`、`vllm`）是无关上游项目的 fork，官方自有仓库实为 8 个。

## 官方 skills 仓库专项

### 它是什么

**是官方的 agent skill 包，不是 MCP，不是框架 SDK。**

- 仓库：`typesafe-ai/skills`，MIT，216 stars / 10 forks，Release **v0.5.7**，最后提交 **Sep 12 2026**
- 仓库描述原文：**"Agent skills for building with TypeSafe's System One API"**
- README 首句原文：
  > "Agent skills for building with [TypeSafe](https://typesafe.ai): typed decisions and probabilities from System One models."
- 官方文档有专页：`docs.typesafe.ai/agent-skill.md`，标题 **"Agent skill"**，副标题原文：
  > "Drop-in skill for Claude Code, Codex, and other agent environments."
- 目录结构（GitHub 文件树）：
  - `.claude-plugin/`（Claude Code 插件市场清单——这就是它同时是 "claude plugin marketplace" 的原因）
  - `skills/typesafe-ai/SKILL.md` + reference files
  - `LICENSE`、`README.md`
- Skill 能力定位（README 原文）：
  > "Design TypeSafe workflows, find current docs and cookbooks, and compose typed judgments in code"

### 怎么用

官方给了三种安装方式（**三选一**，官方明确说"Choose one installation method to avoid duplicate copies"）：

```bash
# 方式 1：Claude Code 插件市场（两条命令）
claude plugin marketplace add typesafe-ai/skills
claude plugin install typesafe@typesafe-ai

# 方式 2：其它 agent 走 skills.sh
npx skills add typesafe-ai/skills --skill typesafe-ai
# 交互式选择你的 agent；默认装到当前项目，加 -g 装全局

# 方式 3：手动 —— 把 skills/typesafe-ai 整个目录（含 reference files）拷到 agent 的 skills 目录
```

调用方式：
- Claude Code 里可直接 `/typesafe:typesafe-ai`
- 任意 agent 都可以在 prompt 里点名：**"use the TypeSafe skill"**
- README 给的示例 prompt 原文：
  > "Use TypeSafe to route incoming support tickets by department, with human review for uncertain decisions."

更新：
```bash
claude plugin marketplace update typesafe-ai
claude plugin update typesafe@typesafe-ai
# 或 /reload-plugins；skills.sh 安装的用 npx skills update
```

### 它是不是官方推荐的 Agent 接入路径？

**是。** 证据链完整：
1. `docs.typesafe.ai/llms.txt` 全站索引里 `agent-skill.md` 是**一级条目**（不是藏在附录），与 `/introduction`、`/api` 平级。
2. 官方文档原文把它描述为 "Drop-in skill for Claude Code, Codex, and other agent environments"，并称它"给 AI coding agent 完整上下文：三种 question types、architectural patterns、构造 evaluations 的最佳实践"。
3. 文档里给了**"Copy to your agent"的整段可粘贴 prompt**，明确列出两种安装命令并优先推荐 Claude Code 插件市场。
4. 文档里有专门的 **"Good vibe coding principles"** 和 **"Common issues"** 章节（含"agent 在编造请求/响应字段"这种运维细节），说明这是官方在维护的一等公民接入面。

### 关键边界（用户最容易误解的点）

- **它是"教 agent 写 TypeSafe 代码"的 skill，不是"让 agent 调用 Jev"的工具。** 装上之后 agent 会知道 request/response 形状、知道要一次多问几个问题、知道去抓哪些 cookbook。它本身不把 Jev 暴露成 tool。
- **它不是 MCP server，官方也没有 MCP server。** 想用 MCP 只能找社区 PoC。
- 官方文档在 Common issues 里亲口承认了一个 agent 常见错误，原文：
  > "Agents aren't great at writing questions, so expect to edit collaboratively with them."
- 判断当前 skill 是否过期的方法（官方原文）：
  > "The agent invents request or response fields. A stale skill can cause this. Update it using your installation method above and retry."

## 逐条发现

### A. 官方接入面

**A1. LangChain 集成是真的，且在 langchain-ai 主仓内，不在 typesafe-ai 组织里。**
`[官方]` docs.langchain.com/oss/python/integrations/providers/typesafe，2026-09-19 抓。
原文要点：
> "TypeSafeClassifier exposes these decisions as a LangChain Runnable, so you can invoke, batch, or compose them with other runnables. It accepts strings, structured JSON, and LangChain message objects, and records traces and token usage in LangSmith."
> "The package includes two experimental middleware that put the classifier on an agent's decision points. Import them from `langchain_typesafe.experimental.middleware`."
> "The middleware are experimental and require `langchain-typesafe[experimental]`. Their APIs may change without notice."

两个 middleware 的 hook 位置（原文表格）：

| Middleware | Hook | Decision |
|---|---|---|
| `ModelRouterMiddleware` | `before_agent`, `wrap_model_call` | Which model handles the run |
| `AutoModeMiddleware` | `wrap_tool_call` | Whether a tool call is too risky to run |

支持用 `TYPESAFE_BASE_URL` 指向兼容网关/私有部署（默认 `https://api.typesafe.ai`）。
注：`langchain-typesafe` 的首次 alpha 是 `0.0.1a1`（引入 `TypeSafeClassifier`），属 pre-stable API。`[二手转述]` tools4all.ai/trends/langchain-ships-langchain-typesafe-001a1-with-typesafeclassifier，2026-09-19 抓。
**重要纠偏**：该包在 **langchain-ai/langchain** 主仓内，**不在** `typesafe-ai` 组织下。`typesafe-ai` 组织 10 个仓库里没有 `langchain-typesafe`、没有 `typesafe-sdk-go`、也没有 MCP server。

**A2. Vercel 侧有两个层次：provider 包 和 Gateway 字符串。**
`[官方]` ai-sdk.dev/providers/ai-sdk-providers/typesafe-ai，2026-09-19 抓。原文关键点：
> "The TypeSafe provider supports the experimental evaluation API with native Choice, Score, and Boolean answers. It sends all questions in one request against the same state."
> "String model resolution and registry integration are not supported yet; pass a model instance."（指 provider 包路径；Gateway 路径可以直接传字符串）
> "TypeSafe returns scores and probabilities rounded to two decimal places. `result.rounding` reports this precision…"
> "Confidence is a separate TypeSafe statistic, available under `result.providerMetadata.typesafe.confidence[questionId]` for Choice and Score answers. Boolean probability always means P(true), not confidence in either outcome."

**命名映射（重要，容易踩坑）**：AI SDK 用 `boolean`/`probability`，TypeSafe 原生叫 `noul`。

| AI SDK 写法 | TypeSafe 原生 |
|---|---|
| `choice` | `Choice` |
| `score` | `Score` |
| `boolean` | `Noul` |
| `result.answers.x.probability` | `.noul` |

**A3. 官方反向适配器 `system-one-adapter-python`（很容易被忽略但很有用）。**
`[一手代码]` github.com/typesafe-ai/system-one-adapter-python，README 全文，2026-09-19 抓。原文：
> "A drop-in replacement for `typesafe_sdk`'s `system_one` evaluation API, backed by LLM APIs instead of TypeSafe."
> "Useful for comparing TypeSafe against an LLM on cost/speed/intelligence."
安装：
```bash
pip install 'system-one-adapter[openai]'      # OpenAI 兼容 provider
pip install 'system-one-adapter[anthropic]'   # 原生 Anthropic
```
版本 **v0.2.0**（2026-09-18 提交），MIT，111 stars。对用户的实用价值：**没排到队 / 想先跑通代码结构时，用它把接口跑通，将来换回 Jev 只改 `provider`**。选项里有 `llm_answer_mode="probabilities"|"discrete"` 和 `normalize_probabilities`（把不合法 LLM 概率分布归一）。
`[二手转述]` blog.csdn.net/2611_96939413/article/details/165869782（2026-09-19 抓）也点明了同一用法："接口一样，将来换回 Jev 只改一个 provider"。

**A4. Braintrust 是目前唯一做了一等适配的可观测/评测平台。**
`[官方]` braintrust.dev/docs/integrations/ai-providers/typesafe，2026-09-19 抓。原文：
> "Tracing records the decision as a question span. It does not automatically create an evaluation score or a Braintrust classification column."
> "Requires Braintrust v3.34.0+ and `@typesafe-ai/sdk` v0.6.0 or later within v0.x."
> "Manual instrumentation — Wrap individual clients with `wrapTypeSafe()` to choose which TypeSafe calls to trace."
> "If your application calls Jev through AI SDK's `experimental_evaluate()`, wrap the `ai` module with `wrapAISDK()`. This requires AI SDK v7.0.103 or later within v7."

另有官方博客讲把 Jev 当 judge scorer：`[官方]` braintrust.dev/blog/evaluate-agent-responses-with-jev，2026-09-19 抓。原文：
> "With a TypeSafe API key, add TypeSafe as an organization provider and then select Jev for the scorer. Native Jev isn't enabled by default. You'll need to request access to use it through Braintrust without a separate TypeSafe key."
> "Jev returns Incorrect, unsafe, or invents information with 0.57 confidence and 0.68 probability."

**A5. 官方 cookbook 的 4 种集成范式（重点：没有一个是"接进 agent 循环"）。**
`[官方]` docs.typesafe.ai/llms.txt 全站索引 + 逐页抓取，2026-09-19。llms.txt 列出的 cookbook 共 **18 个**（背景写的 21 个与本次抓取不符，见"存疑"）：

| Cookbook | 走的范式 | 有没有接第三方框架 |
|---|---|---|
| `function_calling` | 自建 `Dispatcher`：把 `Literal` 闭集参数转成 questions，函数保持原样 | **无**（明确不用 OpenAI tools / LangChain / AutoGen） |
| `semantic_find` | 行级检索：给每行打 `L000` 式 ID → `Choice` 排 255 行，同一请求里 `Noul` 判"文档里到底有没有答案" | **无** |
| `rerank_typesafe` | 重排：`bm25s` + HuggingFace `datasets` 出候选，Jev `Noul` 逐对打分 | 用 `bm25s`/`datasets`，**不是** LangChain/LlamaIndex，也没接向量库 |
| `entity_alignment` | 知识图谱实体对齐：`Score` 三档 = merge / curator queue / leave unlinked，外加逐字段 `Noul` | **无图数据库**（结果只是打印/画图，未接 Neo4j/NetworkX） |
| `llm_guardrails` | 护栏：4 个 hazard `Noul` + 1 个 harm `Score`，同请求；本地 `route()` 按 threshold 分 pass/review/block/support | **无** |
| `parallel_questions` | 批处理：13 问一次调用 vs 13 次单问，**12.2x 便宜 / 10.0x 快** | **无**；且此文结论恰恰是**反对**客户端 fan-out 并发 |
| `skill_suggestion` | agent 技能选择：两阶段渐进披露（182 个技能先粗排 → 前 3 名细看），把获胜技能名塞进 system prompt 的 `<skill_relevance>` 块 | harness 是 **Hermes**（Nous Research），**不是** LangChain/CrewAI；用 `claude-haiku-4-5` 当被测 agent |
| `consistency_noul` / `consistency_choice` | 自洽性实验：同 rubric 跑 15 次比标准差；对照 `claude-haiku-4-5`/`gpt-5.4-mini`/`gpt-5.5`/`claude-opus-4-8` | 有 `anthropic`/`openai` SDK 用于**对照**，不是集成 |

`[官方]` `cookbooks/skill_suggestion` 原文（这是最接近"官方 agent 循环范式"的一篇）：
> "Agents choose skills by truncating and loading them all into the system message, which increases costs, degrades skill selection performance, and induces context rot for the rest of the session. We address this by using two TypeSafe requests per turn, one to rank skills and one to verify the choice, and reduce incorrect skill loads by more than half."
> 实验结果：488 请求下，仅凭 roster 的 agent 错加技能 **16.8%**，带 TypeSafe 建议降到 **7.3%**；无匹配时仍加载从 **9.8% → 4.0%**。

**A6. 官方 patterns 只有 4 个，且都是"代码主导"而非"agent 自主"。**
`[官方]` docs.typesafe.ai/patterns，2026-09-19。Speculative Fan-Out / Confidence-Gated Routing / Composite Scoring / Intent Routing。官方核心哲学原文：
> "System One is TypeSafe's model for building AI-powered software, not agents. It does not generate code or choose its own next action."
`[官方]` docs.typesafe.ai/concepts/how-to-build-with-system-one.md。此页**完全没有**提到 LangChain / LlamaIndex / Vercel AI SDK / Braintrust / observability / MCP。

### C. 执行层：浏览器与桌面自动化

**C1. `browser-use/jev-ultrafast` —— 真实集成，且是"用了 Jev 做判断"的最强案例。**
`[一手代码]` github.com/browser-use/jev-ultrafast（README 全文，2026-09-19 抓）。要点原文：
> "A browser agent with a dynamic, indexed action space. Give it one goal. TypeSafe's Jev picks an operation and an element. A small LLM writes text only when the operation is `TYPE_TEXT`."
> "one TypeSafe request ← page → element table → operation, click_target, type_text_target, select_target (if present)"
> "Two decisions, one network round trip."
> "No screenshots in the default agent loop. Jev consumes structured state. The inspector opts into screenshots."
操作集固定为：`CLICK` / `TYPE_TEXT` / `SELECT` / `SCROLL_UP` / `SCROLL_DOWN` / `WAIT` / `DONE` / `BLOCKED`。
公开基准（README/二手）：Google Flights 苏黎世→伦敦 **7.1s**（前版 9.45s）、浏览器协议调用 **1,092 → 101（-91%）**、Wikipedia 任务 2.798s、本地酒店筛选 1.896s。
`[二手转述]` news.lavx.hu + alphasignal.ai 给出成本约 **$0.0039/run**、MIT 许可。
**该 repo 用的就是"state 表达当前页面状态"的范式**：每个 observation 产出一张带索引的元素表（button / combobox / textbox + label + value），整表进 `state`，问 operation 与 target 两组 `Choice`。

**C2. `awlevin/typesafe-computer-use` —— 真实集成，macOS，OCR 路线。**
`[一手代码]` github.com/awlevin/typesafe-computer-use（README 全文，2026-09-19 抓）。原文：
> "Computer use for about $0.0002 a step: OCR the screen, classify the next action with TypeSafe, click. macOS."
> "It never sends a screenshot to a big model. Instead it reads the screen deterministically, asks a small classifier which action comes next, and only calls a writing model when a text field genuinely needs free text."
流水线原文：
> `screencapture ─► Vision OCR ─► merge lines into blocks ─► drop lines echoing the goal` → accessibility（actionable elements，role/label/frame）→ focused field → AppleScript（frontmost app / pid / active tab URL）→ clock → `dates.py`

### 片段 1：LangChain 官方集成（最推荐的"接进 agent"路径）

出处：`[官方]` https://docs.langchain.com/oss/python/integrations/providers/typesafe （2026-09-19 抓）

```python
# 安装
# uv add langchain-typesafe
# pip install langchain-typesafe
# export TYPESAFE_API_KEY=...
# 可选：export TYPESAFE_BASE_URL=https://gateway.example.com

from langchain_typesafe import Choice, Noul, Score, TypeSafeClassifier

classifier = TypeSafeClassifier(
    questions={
        "urgent": Noul(instructions="Does this need attention right now?"),
        "team": Choice(
            instructions="Which team should pick this up?",
            criteria={
                "infra": "Deploys, availability, and on-call incidents.",
                "billing": "Payments, invoices, and subscriptions.",
            },
        ),
        "severity": Score(

            criteria=["Cosmetic.", "Degraded for some users.", "Full outage."],
        ),
    }

)
```
