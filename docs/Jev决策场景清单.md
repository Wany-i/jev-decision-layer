## 1. 一句话判据（先看这个，再看清单）

**同时满足三条才交给 Jev**：
1. **答案空间能提前穷举**（选项 / 是非 / 有序档位）；
2. **是语义判断，不是算术**（算的在代码里算完再传）；
3. **要高频重复跑**（否则普通 LLM 一次就够）。

**两条共同前提**：`state` 先裁剪 · 输出必带 `confidence` 门控。

## 2. 官方场景地图（`concepts/use-case-map`）

官方把场景分为 **5 大类**：

| 类别 | 官方原话要点 |
|---|---|
| **AI 自动化软件** | 把 AI 与可靠软件交错编排，"能在后台无人值守跑一百万次"。**控制流归代码**，Jev 只做语义判断 |
| **实时应用** | 150ms 级判断，"比人类感知更快"，可嵌进游戏或 UI |
| **大数据上的 AI Map-Reduce** | 便宜 100 倍 ⇒ 可处理巨型语料：找相关信息、给巨型 agent trace 分类、抽特征 |
| **通用校验** | 校验任何其它 AI 的输入 / 抽取 / 推理轨迹 / 工具调用：越狱、引用错误、幻觉、其它错误模式 |
| **Harness 工程** | 让"外壳"变聪明：模型路由、语义上下文检索、错误检测与护栏、推理轨迹分类 |

**10 种任务形状**（官方原表，直接可用作选型表）：

| 决策形状 | 什么时候用它 | 例子 |
|---|---|---|
| **分类** | 有一个已知类别应该胜出 | 意图、主题、部门、风险类型、实体类型 |
| **检测** | 要"某性质存在"的概率 | 垃圾、欺诈、紧急度、越狱、敏感数据 |
| **评分** | 答案属于有序标尺 | 严重度、相关性、质量、挫败感、适配度 |
| **路由** | 类别决定下一步走哪条代码路径 | 工具选择、升级、模型路由、客服队列 |
| **搜索** | 按自然语言查询找匹配项 | 语义搜索、文档发现、候选生成 |
| **检索** | 流程需要最相关的上下文或记录 | RAG 上下文、证据检索、知识查询 |
| **排序** | 按语义相关性/质量排序 | 搜索结果、推荐、候选优先级 |
| **校验** | 要检查某个产物是否有特定失败模式 | 引用支撑、政策违规、工具调用错误、回复质量 |
| **ML 特征抽取** | 下游经典 ML 模型需要语义信号 | 购买意图、产品关注、竞争压力、流失信号 |
| **结构化抽取** | 从非结构化输入恢复已知字段 | 候选人属性、订单字段、文档标签 |

**20 个官方行业场景**（每个都有具体判断点）：检索与搜索、科学发现、模型路由、LLM 护栏、语义代码检查、预测建模特征抽取、招聘、获客、客服、保险理赔、金融犯罪、法律合规、**电商平台**、内容风控与信任安全、**广告**、游戏、风险评估、需求预测、图与知识图谱。

> ⚠️ **对你的重要提醒**：官方"**广告**"这一条写的是——*评估创意素材、活动文案、落地页、投放位置上下文；判品牌安全与受众适配；查合规与禁用声明；评估创意质量与广告-落地页一致性*。
> **它不含"加价/降价/暂停/否词"这类竞价动作**。你想做的那件事属于官方的「分类 + 路由」形状，但**是官方没列的自定义场景** —— 所以更要自己验（见 `Jev广告关键词决策-状态设计与实测.md`）。

## 3. 官方 18 个 cookbook = 厂商自己的实战清单

官网 `docs.typesafe.ai/cookbooks/`，**每一个都是一个"场景 + 可跑的完整做法"**：

| 归到哪类 | cookbook | 官方一句话 |
|---|---|---|
| **检索与排序** | `rerank_typesafe` | BM25 短名单 + 每个"查询-候选"一对一问一次 → top-1 从 5% 提到 18%、top-10 从 38% 到 62% |
| | `semantic_find` | 一次请求给 218 个行 id 打分定位；再用 Noul 判"文档里到底有没有答案" |
| | `classifying_rag_passages` | 给召回段落打分，代码决定哪些进回答模型；把带隐藏指令/注入的丢掉 |
| | `parallel_questions` | 一个请求塞 13 个问题做合规简报：比串行**便宜 12.2 倍、快 10 倍**，答案不变 |
| **分类** | `hierarchical_classification` | 用 Choice 概率做并行 beam search，走专利/零售商品/生物医学/源码的深层层级 |
| | `classification_using_confidence` | 把 SEC 年报分到 75 个行业组；**用 confidence 决定报"细分行业"还是退回"上级大类"** |
| | `entity_alignment` | 从两个啤酒目录的 450 个候选对里判"是不是同一产品"；一个 Score 承载整个判断（合并/不连/交人工） |
| **抽取** | `date_extraction_cookbook` | 抽取绝对与相对日期，代码里解析校验，按置信度人工复核 |
| | `pre_parsed_value_extraction_cookbook` | 正则找候选邮箱/电话/金额，让 Jev 选正确的那个 span，代码做归一化 |
| | `sde_cascade` | 两级结构化抽取级联（mini → verify → reasoning），拿大推理模型的大部分质量、一小部分成本 |
| | `autoformat` | 两次请求恢复 Markdown 结构：一次缝合硬换行，一次给每个块分类 |
| **校验与安全** | `llm_guardrails` | 用一次请求筛掉进出的每条消息：判"是不是越狱"、给危害严重度打分；阈值决定放行/复核/拦截/改道 |
| | `citation_check` | 用源文档查引用是否被幻觉：一个 Choice 判"上下文是否支撑该论断"，confidence 标注人工复核 |
| **Agent 与函数** | `function_calling` | 把自然语言请求映射成"函数名 + 封闭参数集"的带置信度的调用 |
| | `skill_suggestion` | 从 Nous Research 的 182 个技能里给一轮选**至多一个**；第二个请求读 top3 并可全部否决 |
| **一致性** | `consistency_noul_cookbook` | 把不确定的概率路由到人工复核，同时保留原始 noul 值可见 |
| | `consistency_choice_cookbook` | 给审核决策加一个"不确定"出口，对比标签一致率与自动执行占比 |
| **科研/建模** | `autoresearch_feature_discovery` | 自动提出 Jev 问题、把自由文本转成数值特征，用模型误差改进下游 CatBoost 回归器 |

**4 个官方模式**（怎么组合着用）：Speculative Fan-out（一次性问一批，含只在某分支才用的问题）/ Confidence-gated Routing（答案告诉你"是什么"，置信度告诉你"该不该动手"）/ Composite Scoring（拆成原子 Score，权重在代码里控制）/ Intent Routing（分类后分别送确定性逻辑、专用 LLM 或人）。

## 4. 网页 / 桌面 / 移动操作（社区主导，官方无 cookbook）

**重要事实**：官方 18 个 cookbook **没有任何一个**涉及 browser / computer-use / desktop。
→ 这条线是**社区探索出来的，没有官方背书**，所以风险更高、更要自己测。

**另一个事实**：我核实到的 7 个社区实现**全部走原生 `api.typesafe.ai/v1/systemone`**，不走 OpenRouter（你手上的 key 能调，但要清楚这条差异）。

### 20 条执行层决策（骨架，完整五项见 §0 那份文件）

| 组 | 决策 |
|---|---|
| **A 动作空间** | D1 动作类别 · D2 目标元素 · D3 元素分组路由（两阶段）· D4 站点/搜索源 · D5 屏幕外控件 · D6 元素级语义分类 |
| **B 终止与异常** | D7 目标是否达成 · D8 是否在打转 · D9 报错分类 · D10 是否撞登录墙 · D11 是否被硬阻断 |
| **C 风险闸门** | **D12 下一步动作是否不可逆** · D13 确认/取消 |
| **D 值决策** | D14 文本值 · D15 地址 · D16 滚动方向与幅度 · D17 下拉选项 · D18 输入是否已落地 |
| **E 导航理解** | D19 多级菜单走向 · D20 是否在跟浏览器说话 / 是否说完 |

**最值得照抄的是 D12**：用 `noul` 问"下一步动作是否不可逆"，代码按 0.5 阈值闸门。
理由：**它是唯一漏判会造成真实损失的决策，也是唯一"既便宜到可以每步都问、又只有模型能判"的决策**。

**两个必答题（来自实测与官方限制）**：
1. **看不了截图** → 页面状态必须先文本化（社区实现里的具体字段清单见那份文件第二节）；
2. **算术不可靠** → 滚动幅度、坐标、等待时间这类必须在代码里算。

## 6. 反面清单：什么别交给它

| 别交 | 官方依据 |
|---|---|
| 算术、计数、百分比、差异 | 失败模式 #2："不是计算器"、**计数不可靠，误差随规模增长** |
| 日期先后、天数、周几 | 失败模式 #3：日期被当文本读 |
| 生成文本、写文案 | 失败模式 #9：不生成文本（硬凑会很慢很糟） |
| 开放式推理、多跳、复合判断 | 失败模式 #4：多级间接掉准确率；官方要求"一句话一个判断" |
| 看截图、看图、看音视频 | 仅文本输入（`input_modalities: ["text"]`） |
| 拿 `score` 插值还原具体数值 | 官方："score levels are weak in numerical calibration" |
| 把 `noul` 和 `choice` 的数互相换算 | 失败模式 #8：同题 0.22 vs 0.01；两个相反 `noul` 相加 1.19 |
| 让它自己从长文档里"找相关" | 失败模式 #5：**context rot**，先在你的代码里检索裁剪 |
